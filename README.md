# Парсер УПД (polling-демон в Docker)

Демон следит за сетевой папкой со сканами, нарезает пакетные PDF на отдельные
УПД, извлекает номер/дату/ИНН/сумму, определяет наличие печати и приложений
и ведёт реестр в Excel. Оригиналы не изменяются (папка входа монтируется
только для чтения).

## Архитектура

- **Polling вместо watchdog** — проверка папки каждые 30 секунд. Надёжно
  работает на сетевых шарах и не зависит от inotify.
- **Текстовый слой в приоритете** — если МФУ делает OCR сам (Kyocera, Canon,
  HP и др.), обработка страницы занимает миллисекунды. Если текста нет —
  Tesseract, причём для поиска заголовков распознаётся только верх страницы.
- **Автоповорот страниц** — сканы, повёрнутые на 90/180/270°, определяются
  через OSD Tesseract и поворачиваются перед распознаванием.
- **Бинаризация и чистка таблиц** — перед OCR изображение бинаризуется
  (Otsu), а в зоне итогов удаляются линии таблицы: качество распознавания
  номеров, ИНН и сумм заметно выше.
- **Слияние страниц-продолжений** — если вторая страница УПД повторяет
  заголовок формы с тем же номером, она включается в текущий документ,
  а не нарезается как новый.
- **Честный реестр** — если сумму или дату распознать не удалось или год
  выглядит неправдоподобно, в колонке «Примечание» ставится флаг проверки
  вместо молчаливой подстановки мусора.
- **Дедупликация по SHA-256** — хэши обработанных файлов хранятся в
  `processed.db`; повторное сканирование того же файла будет пропущено,
  перезапуск контейнера не создаёт дублей.
- **Атомарная запись Excel** — реестр пишется во временный файл с заменой,
  файл не побьётся при внезапной остановке.
- **Страницы без заголовка УПД** не теряются — складываются в
  `_разобрать_вручную/`.

## Структура папок на NAS

```
/volume1/Scanner/
├── input/    ← сюда сканирует МФУ (в контейнер монтируется read-only)
└── output/   ← результаты: нарезанные УПД, реестр_упд.xlsx, processed.db,
                logs/, _разобрать_вручную/
```

## Деплой

1. Скопируйте файлы проекта (`app.py`, `Dockerfile`, `requirements.txt`,
   `docker-compose.yml`) в любую папку на NAS, например `/volume1/docker/upd-parser/`.
2. В `docker-compose.yml` поправьте пути к вашим папкам `input`/`output`.
3. По SSH:

```bash
cd /volume1/docker/upd-parser
docker compose up -d --build
```

Либо через Container Manager (бывший Docker): создайте проект из
`docker-compose.yml`.

Логи: `docker logs -f upd_parser` или файл `output/logs/processor.log`.

## Настройки (environment в docker-compose.yml)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `POLL_INTERVAL` | `30` | Пауза между проверками папки, сек |
| `OCR_DPI` | `200` | Разрешение рендера для OCR (200–250) |
| `OCR_LANG` | `rus+eng` | Языки Tesseract |
| `HEADER_ZONE` | `0.45` | Доля страницы сверху для поиска заголовка |

## Обслуживание

- **Архивация input**: контейнер физически не может удалять оригиналы
  (read-only). Настройте на шаре «Планировщик задач» скрипт, переносящий
  файлы старше N дней в архив:
  `find /volume1/Scanner/input -name '*.pdf' -mtime +14 -exec mv {} /volume1/Scanner/archive/ \;`
- **Сброс журнала обработанных**: удалите `output/processed.db` — все файлы
  будут обработаны заново.

## Возможные доработки

- **QR-сепараторы**: вставка листов со штрих-кодом между документами при
  сканировании даёт 100% точные границы без OCR заголовков (библиотека
  `pyzbar`, системный пакет `libzbar0`).
- **PaddleOCR вместо Tesseract**: на слабых/замусоренных сканах точнее.
  Функция `extract_text()` изолирована — достаточно заменить одну строку
  вызова, добавив `paddlepaddle` + `paddleocr` в requirements.
